# Event awards — deploy

Spec: `docs/superpowers/specs/2026-09-22-awards-design.md`.

## What ships

- Migration `0046_*`: `award_grants`, `award_uploads`, and `booster_kit_challenges.award_grant_id`.
  Applied by `deploy/deploy-release.sh`, which stops the bot, worker and web first.
- The bot's `/award grant|revoke|list` (ManageGuild), and the placement tick now places awards too.
- The worker uploads `./custom/awards.json` every sweep where it changed.
- `/awards` and `/awards/<id>` on the site.

## Before the release

1. **Class names exist on the server.** CI cannot see the mission. From the parent directory:

       for c in $(node -e 'const a=require("./clan-wars/packages/domain/assets/awards.json");for(const d of Object.values(a))for(const s of Object.values(d.slots))for(const i of s.items)console.log(i.className)'); do
         grep -q "name=\"$c\"" livonia/db/types.xml || echo "MISSING $c"
       done

   Expect no output. A missing class spawns nothing and raises no error.

## After the release

⚠️ **Grant nothing until step 2 is done and step 3 has confirmed the file.** An award's
week starts from the first upload that carries it (spec §5.2), and the worker cannot tell
whether the server actually loads the file. A grant placed before `awards.json` is in
`objectSpawnersArr` runs its clock with nothing on the ground. The same applies whenever a
`livonia` Release has overwritten `cfggameplay.json`: check the entry is still there
before an event hands out prizes.

2. **Register the spawner file once, by hand.** Nothing in this codebase adds entries to
   `objectSpawnersArr`. `applyGameplay` only splices the airdrop entry and must stay the only writer.
   In the mission's `cfggameplay.json`, add `"./custom/awards.json"` to `WorldsData.objectSpawnersArr`,
   next to `"./custom/booster-kits.json"`. ⚠️ The `livonia` repo FTPs `cfggameplay.json` on every
   published Release, so make the same edit in that repo, or the next Release removes it.
3. **Check the file.** `docker compose logs ingest-worker | grep "award file"`. You should see one
   line with `0 award(s), uploaded`, and the file in the mission's `custom/` directory holding
   `{"Objects":[]}`.
4. **Try it end to end.** `/award grant user:<you> award:Plate Carrier reason:Deploy check`, follow
   the DM, pick three pieces, do the emotes, and confirm the worker logs `1 award(s), uploaded … 1 clock(s)
   started`. At the next restart, find it in game. Then `/award revoke` it and confirm the next upload
   drops it.

## Rollback

`/award revoke` every open grant (`/award list`) and wait one sweep. The file becomes
`{"Objects":[]}`. Then remove `./custom/awards.json` from `objectSpawnersArr` (in the `livonia` repo
too). The tables can stay; nothing reads them once the code is rolled back.
