# The map (increment 5) — deploy runbook

Migration 0025 adds `player_positions`, `intruder_sightings`, and `clan_pins`. Nothing is
dropped. The bot gains the positions tick (backfills positions from `events`, commits per
batch), the zone watch consumer (detects intruders within `WATCH_ZONE_RADIUS_M` = 100 m of
declared bases, running every tick), and the reaper (deletes positions and sightings past
their retention windows, every 5 min alongside pending expiry).
The site gains `/map` with layers for declared bases, intruders, travel points, and a 1 km
grid; `/map` itself reads base visibility rules (linked member only, dormant clans visible).
`scripts/wipe.ts` is the wipe (clears `pinsCleared` and `sightingsCleared`).

1. **Verify the gate and dismantle lines against the live log** — Run this read-only query
   against `factions_live`:

       select content from raw_lines where content ~ '\)\s*(Built|Dismantled) ' and content !~ 'Flag Pole' order by id desc limit 20

   (`\s*` after the paren, because `structure.ts`'s regex allows a space there — a log
   that emits `) Built` parses fine and must not be missed by the check meant to prove it.)

   Confirm the lines match `Built <part> on <structure>[ with <tool>]` / `Dismantled <part>
   from <structure>[ with <tool>]` and that at least one gate line's part or structure
   contains "gate". If not, stop and adjust `structure.ts` before deploying. **The deploy
   stops if the lines do not match.**

2. **Verify the tiles**: Run `ls /var/www/tiles/enoch/topographic/0/0/0.webp`. If absent,
   run One Life's `deploy/mirror-tiles.sh` (its README's "Owner-only life map tiles" section).

3. **Reload nginx** with the new `location /tiles/` block: `sudo nginx -t && sudo systemctl
   reload nginx`. ⚠️ Reload, never restart — four sites.

4. **Read and apply migration 0025** with the one-off runner from
   `docs/deploy/2026-09-02-dormancy.md`. The bot may keep running while it applies; restart
   it after.

5. **Seed both consumer cursors, BEFORE the restart.** `consumer_cursors` is
   `@factions/event-log`'s table: `consumer_name` (primary key), `last_event_id`,
   `updated_at`. Without this, `readCursor` returns `0` on the first tick and both new
   consumers drain the whole historical `events` table — the zone watch judging weeks-old
   fixes against *today's* declarations and queueing real Discord alerts for every one.
   Seed `zone-watch` at the log head, and `positions-projector` at the last event *outside*
   the 30-day retention window (so the backfill covers exactly the retained history):

       insert into consumer_cursors (consumer_name, last_event_id, updated_at)
       select 'zone-watch', coalesce(max(id), 0), now() from events
       on conflict (consumer_name) do update
         set last_event_id = excluded.last_event_id, updated_at = now();

       insert into consumer_cursors (consumer_name, last_event_id, updated_at)
       select 'positions-projector', coalesce(max(id), 0), now() from events
       where occurred_at < now() - interval '30 days'
       on conflict (consumer_name) do update
         set last_event_id = excluded.last_event_id, updated_at = now();

   Verify before restarting:

       select consumer_name, last_event_id from consumer_cursors
       where consumer_name in ('zone-watch', 'positions-projector');
       select max(id) from events;

   `zone-watch` must equal `max(id)`; `positions-projector` must be at or below it (it is
   `0` if every event is inside the 30-day window, which is correct — there is nothing to
   skip).

   **If the bot was restarted first:** stop it (`sudo systemctl stop clan-wars-bot`), run
   the two statements above, then delete the queued-but-unposted alerts before starting it
   again —

       delete from clan_notices
       where posted_at is null and failed_at is null
         and kind in ('intruder', 'dismantle', 'gate_built', 'solo_intruder', 'solo_dismantle', 'solo_gate');

   Anything already posted cannot be recalled; delete only the rows that have not gone out.

   ⚠️ Belt and braces: the code carries the same guard. `zoneTick` skips any fix older than
   `INTRUDER_PIN_TTL_MS` and `positionsTick` skips any fix older than
   `POSITION_RETENTION_MS`, advancing the cursor past them either way. That makes a missed
   seed **noisy-but-bounded** (a burst of last-hour fixes re-judged) rather than
   catastrophic (the whole log). Seed anyway — the guard is the fallback, not the plan.

6. **Deploy bot and web together**: `docker compose build web && docker compose up -d web &&
   sudo systemctl restart clan-wars-bot`.

7. **Verify the projection** — Open `/map` as a linked member, switch on Travel points, and
   check that the Fast Travel Hub marker sits on the Hub's building at `100, 93` in the
   south-west corner and that a known travel point sits on its outhouse/well/bus stop. A
   uniformly offset or scaled overlay means `MAX_ZOOM`/`CANVAS_PX` in
   `apps/web/lib/map-projection.ts` is wrong for the mirrored pyramid.

8. **Confirm over the first ticks** (`journalctl -u clan-wars-bot -f`, tick interval
   `BOT_TICK_INTERVAL_MS`, default 10 s): `positions: N fix(es)` on the first tick (the
   backfill of the retained history from the seeded cursor — expect it to take a few ticks
   for a busy 30 days; the cursor commits per batch). Then `zone watch: …` lines and
   `#clan-…` intruder notices as players walk near bases.

9. **The wipe** now reports `pinsCleared`/`sightingsCleared`. Also: the "Position fix cadence"
   number is the server's, not ours; with step 5's seed the first positions backfill writes
   nothing older than 30 days, because the cursor starts past it — and without the seed
   `positionsTick`'s own guard skips those older fixes anyway, so nothing the reaper would
   delete on its next 5-minute pass is ever written.

⚠️ **After a manual reset of the `zone-watch` consumer cursor**, dismantle/gate alerts inside
the rewound range post again (sightings do not; they are keyed on the row) — so never rewind
that cursor casually. The code's `INTRUDER_PIN_TTL_MS` guard bounds the damage to events of
the last hour, however far back the cursor is rewound.
