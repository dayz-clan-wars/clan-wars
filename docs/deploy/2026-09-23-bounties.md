# Bounties — deploy

Spec: `docs/superpowers/specs/2026-09-23-bounties-design.md`.

## What ships

- Migration `0048_dusty_harrier.sql`: adds only the `bounties` table.
- The bot's `/bounty place|revoke|list` (ManageGuild).
- `bounty-tick.ts` (claim/expire, after `killsTick`) and `bounty-announce-tick.ts`
  (WANTED/collected/lifted posts, after the restart tick).
- The Bounties layer on `/map`, visible to every linked viewer.
- The tenth leaderboard, Most bounty kills (`bounty-kills`), with an optional crown role.

## Before the release

1. **Migration 0048 only adds a table.** The release deploy applies it after stopping
   the writers, same as every other migration — there is no manual stop-first step here,
   because nothing existing reads or writes `bounties` yet.

## After the release

2. In `.env`, set `BOUNTY_TICK=true`. `SERVER_EVENTS_CHANNEL_ID` must already be set —
   the bot refuses to start otherwise, with a line naming both (a bounty is announced
   there, and an unannounced bounty is a punishment nobody knows about). Optionally set
   `CROWN_BOUNTY_KILLS_ROLE_ID` to a role created by hand, the same way the other nine
   crown roles work. Left unset, no crown role is touched.
3. ⚠️ On the first start with ten boards, `#leaderboards` is purged and reposted once —
   the leaderboard tick's "any missing" rule (see the leaderboards runbook). That is
   expected, not a fault.
4. The `/bounty` command registers at bot start, the same as every other slash command.
   It is visible only to members with Manage Server.
5. **Acceptance.** Place a bounty on a test character with `hours:1`. See the WANTED
   post in the server events channel, and the DM if the character is linked. From a
   second linked account in no clan, see the pin on `/map`. Kill the character from an
   account in a different clan and check that the "collected" post lands and the
   Most bounty kills board shows 1. Place another bounty and `/bounty revoke` it: check
   the "lifted" post, and that the pin is gone on the map's next poll.
6. **Turning it off.** `BOUNTY_TICK=false` leaves any open bounty open and on the map,
   unclaimed and unexpired (spec §5) — the tick that would resolve it just stops running.
   Revoke open bounties first if they should disappear.

## Rollback

Set `BOUNTY_TICK=false`. Open bounties stay open (see above); revoke them with
`/bounty revoke` first if they should come off the map. The `bounties` table can stay —
nothing else reads or writes it once the tick is off.
